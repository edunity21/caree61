# 진로전담교사 심층면접 · 66문항 (중·고 공통)

2027학년도 중등 진로전담교사 선발 **2차 전형(심층면접)** 대비 연습 도구입니다.
239문항 자료를 재구성한 48문항에서 **12문항을 덜어 낸 36문항**에 **상담이론 5문항**과 **원본 통합 20문항**과 **교재 5문항**을 더한 **66문항**이며, 239문항 원본은 전량 반영되었습니다.
선발계획과 2차 전형 실시계획의 평가요소를 문항마다 연결했습니다.

## 48 → 36으로 덜어 낸 기준

빠진 12문항은 **행정·조직 실무형**(법적 근거와 역할 재정립, 연간계획과 성과환류, 상담 기록 관리,
교내 협력체계, 조직·공간·지역 연계, 체험처 발굴과 돌발상황)과 **개인 이력형**(전직 동기, 보직·연수 경력),
그리고 다른 문항에 흡수되는 주제(교과연계 진로교육, 학부모 진로교육, CAIT, 대입제도 개편)입니다.
남은 36문항은 2차 전형 평가 주안점 ②(진로진학 전문지식·상담이론 이해·상담능력)에 정면으로 걸립니다.

## 37~41 — 상담이론 보강 (신설)

평가 주안점 ②의 **상담이론 이해·상담능력**에 비해 기존 36문항의 이론 커버리지가 얇다고 판단해 5문항을 신설했습니다.
기존 22번(홀랜드)·23번(긴즈버그·수퍼·타이드만·크롬볼츠)과 중복되지 않는 영역만 골랐습니다.

|---|---|---|---|
| 37 S | 검사·이론 | 사회인지진로이론(렌트·브라운·해켓) + 반두라 자기효능감 | 기존 문항 어디에도 없던 **효능감·결과기대·진로장벽** 축. "왜 시도조차 하지 않는가"를 설명하는 유일한 이론 |

## 사용법

- 왼쪽에서 영역·등급으로 범위를 좁히고, 문항을 고르면 제시문과 하위질문 3개가 나옵니다. 키워드와 모범답안은 처음에 가려져 있습니다.
- `⏱ 3분 시작` — 실전 3분이 기본이며, 구상 40초 / 답변 2분 20초로 나누어 연습할 수도 있습니다.
- `🔊 읽어주기` — 0.8~2.0배속. 답안 구간을 누르면 그 지점부터 읽습니다.
- `▶ 연속 재생` — **문항 낭독 → 모범답안 낭독 → 다음 문항**으로 자동 진행합니다. 구상 대기는 두지 않았습니다.
  - **왼쪽 필터로 좁힌 범위만** 순회합니다. 상담 영역만, S 등급만 듣는 식으로 쓸 수 있습니다.
  - 범위 선택 — `문항 + 답안` / `답안만` / `문항만`. `답안만`은 이동 중 통독에, `문항만`은 구상 훈련에 씁니다.
  - `끝나면 처음부터`를 켜면 반복 재생합니다. 선택값은 다음 방문에도 유지됩니다.
  - 목록·`이전`·`다음`을 직접 누르면 연속 재생이 끊깁니다. `Esc`나 `■ 정지`로도 멈춥니다.
  - 재생 중에는 **화면 잠금을 막습니다**(Screen Wake Lock). 화면이 꺼지면 브라우저 음성이 중단되기 때문입니다.
  - 안드로이드 크롬에서 낭독이 신호 없이 끊기는 경우를 대비해 **감시 타이머**를 두어 다음 구간으로 넘어갑니다.
- `⛶ 넓게 보기` — 우측 상단 버튼 또는 `F` 키. 키보드 `←` `→` 이동, `Space` 문항 낭독, `Esc` 정지·해제.

## 모바일 (v4)

기존 `전체화면` 버튼에는 두 가지 문제가 있었습니다.

- **안드로이드** — `requestFullscreen`은 정상 동작해 주소창이 사라지지만, CSS에서 전체화면 상태가 하는 일이 `body.is-full .shell{max-width:1400px}` 한 줄뿐이었습니다. `.shell`은 이미 1240px이고 휴대폰 폭은 400px 안팎이라 **페이지가 전혀 재배치되지 않았습니다.** 상단바·목록·좌우 여백이 그대로 남아 확보된 공간이 보이지 않았습니다.
- **아이폰 사파리** — `requestFullscreen` 자체를 지원하지 않아 코드가 빈 함수를 실행하고 끝났습니다.

`넓게 보기`로 이름을 바꾸고, **좁은 화면에서는 브라우저 UI 숨김과 페이지 레이아웃 접기를 함께** 적용합니다.
전체화면 API가 없는 환경에서는 레이아웃 접기만으로 동작합니다. 데스크톱은 기존 동작(목록 유지 + 폭 확대)을 유지합니다.

| 항목 | 조치 |
|---|---|
| **넓게 보기** | 상단바·목록·출처를 접고 본문만 남깁니다. 안드로이드는 주소창 숨김까지 함께. 해제는 우하단 `⤡ 해제`, `Esc`, 또는 안드로이드 뒤로가기 |
| **타이머 위치** | 상단바 높이를 실측해 `--topbar-h`로 반영. 안드로이드 글자 크기 확대 설정에서도 타이머가 가려지지 않습니다 |
| **상단바** | 부제·`연습 완료` 라벨을 접고 제목을 한 줄로 고정. 제목 줄바꿈으로 두꺼워지던 문제 해결 (약 26px 확보) |
| **본문 폭** | 상세 카드를 화면 끝까지 붙이고 좌우 여백을 30px → 14px로 축소 |
| **도구 줄** | `flex:1 1 auto` 균등 늘림을 6열 격자로 교체 — 버튼 2개 / 선택 3개가 두 줄에 정렬 |
| **타이머** | 구동 중에는 화면 상단에 고정. 답안을 내려 읽어도 남은 시간이 보입니다 |
| **이동 버튼** | `← 이전 · 무작위 · 다음 →`을 하단에 고정. 긴 답안을 끝까지 내리지 않아도 이동 가능 |
| **안전영역** | `env(safe-area-inset-*)` 적용 — 노치·홈 인디케이터와 겹치지 않습니다 |
| **≤400px** | 전형 안내 표를 세로로 풀고, 도구 줄을 2열로 |
| **가로 모드 (높이 ≤520px)** | 상단·하단 고정을 모두 해제해 본문 높이를 확보 |
| **뷰포트 높이** | `100vh` → `100dvh` (지원 시). 주소창 여닫힘에 따른 잘림 방지 |

## 배포

압축을 풀어 `index.html` `style.css` `app.js` `data.js` `.nojekyll` 을 저장소 최상단에 올리고 Settings → Pages에서 브랜치를 지정하십시오.
`questions.json`은 원본 데이터, `qa_data.py`는 기존 `make_mp3.py`에 넣어 쓰는 MP3용 파일입니다.

## 연속 재생과 MP3의 역할 구분

브라우저 음성 합성은 **화면이 켜져 있고 탭이 앞에 있을 때만** 안정적으로 동작합니다.
화면을 끄거나 다른 앱으로 넘어가면 음성이 멈추므로, 이동 중 듣기나 취침 전 듣기에는
`make_mp3.py`로 만든 MP3가 여전히 더 확실합니다.
`▶ 연속 재생`은 화면을 보며 구간 강조를 함께 따라갈 때 쓰는 기능입니다.

## v15 — 연속 재생 오류 수정

연속 재생이 중간에 멈추거나 두 음성이 겹쳐 들리던 문제를 고쳤습니다. 원인은 네 가지였습니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| **한 문항에서 두 목소리가 겹쳐 읽힘 · 답안 일부가 건너뛰어짐** | 정지할 때 부르는 `speechSynthesis.cancel()` 은 직전 발화에 `onerror`(interrupted)를 **뒤늦게** 돌려줍니다. 그 신호가 이미 시작된 다음 재생의 재생 위치(`idx`)를 덮어쓰고 감시 타이머를 지워, 재생 흐름이 두 갈래로 갈라졌습니다 | 재생마다 **세대 번호**를 붙여, 지난 재생이 돌려주는 `onend`·`onerror` 는 전부 버립니다 |
| **문항이 끝난 뒤 20초 가까이 조용하다가 이어짐 · 아예 멈춤** | 크롬은 `cancel()` 바로 뒤의 `speak()` 를 소리 없이 무시합니다. 문항→답안, 답안→다음 문항으로 넘어갈 때마다 여기에 걸렸습니다 | 자연 종료에는 `cancel()` 을 부르지 않고, 말하는 중일 때만 취소한 뒤 잠깐 두었다 시작합니다. 1.5초 안에 소리가 시작되지 않으면 **한 번 더 요청**합니다 |
| **긴 구간에서 다음 구간이 먼저 끼어듦** | 감시 타이머를 발화를 **요청한 시점**에 걸어 두어, 앞 구간이 아직 말하는 중인데도 시간이 흘렀습니다 | `onstart` 로 **실제로 말을 시작한 뒤부터** 시간을 재고, 예상 시간도 한국어 낭독 속도에 맞춰 늘렸습니다 |
| **`🔊 문항 읽어주기` 를 누르면 콘솔에 오류** | `onclick = readQuestion` 으로 연결해 **클릭 이벤트가 완료 콜백 자리**에 들어갔고, 낭독이 끝나는 순간 `done is not a function` 이 났습니다 | 콜백을 감싸 넘기고, 함수가 아닌 값은 무시합니다 |

함께 손본 것

- 탭을 잠시 벗어났다 돌아오면 멈춰 있던 음성을 다시 잇습니다(크롬은 화면이 가려지면 스스로 일시정지합니다).
- 연속 재생 중 **답안 구간을 누르면 그 구간부터 이어서** 순회를 계속합니다. 이전에는 거기서 흐름이 끊긴 채 버튼만 `정지` 로 남았습니다.
- `🔊 문항`·`🔊 모범답안`·`Space` 로 직접 낭독하면 연속 재생을 정리하고 시작합니다.
- 완료 신호가 늦게 두 번 들어와도 문항을 한 번만 넘기도록 단계 번호를 붙였습니다.

`index.html` 의 스크립트 주소를 `app.js?v=15` 로 올렸습니다. 브라우저가 옛 파일을 들고 있으면 증상이 그대로이니 함께 올리십시오.

## 문항 수 표기 정정

`build_docx.js` 만 **61문항** 시절 문구가 남아 있었습니다. 표지 큰 숫자, 문서 속성 제목,
주석이 모두 61이었고 저장 파일 이름만 66이라 서로 어긋난 상태였습니다.
데이터(`questions.json`·`data.js`)와 웹앱은 처음부터 66문항이 맞습니다.

숫자를 손으로 적어 두면 문항이 늘 때마다 같은 일이 반복되므로,
표지·제목·파일 이름을 모두 `ITEMS.length` 에서 뽑도록 바꿨습니다. 이제 문항을 더하면 표기가 따라옵니다.

## 웹에서 61문항으로 보이는 경우

제목은 66인데 목록이 61이면, **배포된 `data.js` 가 62~66번이 들어가기 전 판**입니다.

| 구간 | 문항 | 누적 |
|---|---|---|
| 기존 | 1~36 | 36 |
| 상담이론 보강 | 37~41 | 41 |
| 원본 통합 | 42~61 | **61** ← 여기까지가 옛 판 |
| 교재 반영 | 62~66 | 66 |

61은 우연한 숫자가 아니라 직전 판의 마지막 번호입니다. `index.html` 의 제목은 손으로 적어 둔 글자라
`data.js` 가 옛 파일이어도 66이라고 그대로 표시됐고, 목록만 61로 나온 것입니다.

조치 두 가지입니다.

- 제목·진행률·안내문의 문항 수를 **모두 `data.js` 에서 세어 쓰도록** 바꿨습니다. 이제 옛 파일을 올리면 제목도 61로 바뀌므로 어긋난 채 지나가지 않습니다.
- `data.js` 주소를 `?v=66-2` 로 올렸습니다. 옛 파일이 브라우저나 CDN에 남아 있어도 새로 받아 옵니다.

`index.html` `app.js` `data.js` 세 개를 **함께** 올리셔야 합니다. `data.js` 를 빼면 목록은 그대로 61입니다.
올린 뒤 상단 제목이 `· 66문항`, 진행률이 `/66` 으로 보이면 정상이고,
브라우저 콘솔에도 `문항 수 66 · 마지막 번호 66` 이 찍힙니다.

## v17 — 일부 구간이 두 번 읽히던 문제

v15에서 "소리가 나지 않으면 한 번 더 요청한다"는 장치를 넣었는데, 이것이 과하게 작동했습니다.
원인은 세 가지이고 모두 같은 결과 — **같은 구간이 두 번 읽힘** — 로 이어졌습니다.

| 원인 | 무슨 일이 일어났나 | 조치 |
|---|---|---|
| **같은 발화를 취소 없이 다시 요청** | 안드로이드 크롬과 네트워크 음성은 `speak()` 를 받아 놓고도 소리가 날 때까지 `speaking`·`pending` 을 `false` 로 둡니다. 멈춘 줄 알고 다시 요청하면 **브라우저 큐에 둘 다 남아** 그 구간이 연달아 두 번 읽힙니다 | 다시 걸기 전에 `cancel()` 로 숨은 것을 먼저 지우고, 새 발화 객체로 **한 번만** 겁니다. 기다리는 시간도 1.5초 → 2.8초로 늘려 느린 음성을 성급히 다시 걸지 않습니다 |
| **`resume()` 가 구간을 처음부터 되감음** | 크롬은 `resume()` 이 읽던 구간을 처음부터 다시 읽는 경우가 있습니다. 4초마다 상태를 점검하며 `resume()` 을 부르고 있었습니다 | 재생 중에는 건드리지 않습니다. 완전히 멎어 있을 때(`paused` 이면서 `speaking` 이 아닐 때)만, 그것도 10초 간격으로 한 번 풀어 줍니다 |
| **`■ 정지` 를 눌러도 남은 구간이 뒤늦게 터져 나옴** | 정지할 때 "말하는 중일 때만 취소"하도록 해 두어, 큐에 남았는데 `speaking` 이 `false` 로 보이면 취소를 건너뛰었습니다. 그 구간이 다음 문항 위로 겹쳐 나왔습니다 | 정지에서는 상태와 무관하게 **항상 취소**합니다. 대신 취소 시각을 기억해 두었다가 다음 낭독을 0.18초 뒤에 시작해, 취소 직후의 `speak()` 가 무시되는 크롬 문제를 함께 피합니다 |

감시 타이머도 손봤습니다. 예상 시간이 지나도 **아직 말하는 중이면 최대 15초까지 기다립니다.**
이전에는 그냥 다음 구간으로 넘어가 앞뒤가 겹쳐 들렸습니다.

`app.js?v=17` 로 올렸습니다. `index.html` 과 `app.js` 를 함께 올리십시오.
